# H30.1 Shared Shell and Visual Foundation Contract

Status: active shared-shell and visual-foundation contract established by `H30`.

## Purpose

Record the implementation contract that `H30` established for the shared shell and visual foundation.

This task doc remains the active source of truth for the authenticated shared-shell baseline. It exists to keep `H30` from drifting into page-specific table, form, or dashboard redesign and to give `H31`-`H34` a stable shell/foundation contract to inherit rather than re-decide.

`H30` covers the shared-shell and foundation migration layer for the broader UI modernization wave. It establishes the Bootstrap 5-compatible, ScholarDex-owned shell baseline that later `H31`-`H34` work builds on.

## Current Baseline

- The current shared shell source of truth is `src/main/resources/templates/fragments.html`.
- Runtime templates consume the frontend asset contract through `/assets/app.css` and `/assets/app.js`.
- Authored frontend changes flow through `frontend/src/**` and the existing asset build pipeline.
- The migrated authenticated shell now owns the shared sidebar, topbar, page-header, theme toggle, and shell-level layout primitives through shared fragments plus repo-owned frontend modules.
- Root theme state for migrated shell work is expressed through `data-bs-theme` on the root element, with repo-owned initialization and persistence behavior.
- Shared route pages must preserve the unified sidebar composition path.
- Canonical route families and canonical template naming remain governed by `docs/frontend-conventions.md`.
- SB Admin 2 styling/JS, Bootstrap 4-era shell markup/classes, related jQuery-driven shell behavior, and Bootstrap 4-oriented third-party UI coupling are still present in the runtime today.
- For touched shared-shell areas migrated by `H30`, that legacy frontend stack is retired migration debt rather than an acceptable baseline to preserve.

## Locked Direction

- The shared shell should become quieter, clearer, more visually consistent, and explicitly owned by ScholarDex rather than a third-party admin template baseline.
- Sidebar, topbar, page-header hierarchy, spacing, typography, shell-level surface treatment, and shared shell behavior are in scope for `H30`.
- Bootstrap 5 is the intended frontend baseline for touched shared-shell implementation.
- ScholarDex-owned UI/UX patterns defined by `docs/ux-design-guide.md` are the intended shell/design baseline.
- Light and dark themes are supported presentation modes within that design system.
- `H30` establishes the shell/foundation baseline that later tasks build on, rather than attempting to redesign the entire UI surface in one slice.
- `H30` shared-shell work is expected to move touched shell areas away from SB Admin 2, Bootstrap 4-era shell assumptions, and jQuery-driven shell behavior where those dependencies conflict with the intended baseline.
- `H31`-`H34` inherit the shared shell ownership model, root theme-state contract, shared layout primitives, and Bootstrap 5 migration direction established by `H30`.

## In Scope

- Shared sidebar grouping, labels, active-state treatment, icon consistency, shell-level spacing, and shared sidebar behavior.
- Shared topbar, page-title, and context/orientation treatment, including improvement of current role/context affordances inside the shared shell.
- Shell-level spacing rhythm, typography hierarchy, bounded content layout, card/surface baseline, and theme hooks only where those conventions are part of the shared shell/foundation layer.
- Shared-fragment updates plus the supporting frontend asset changes needed to express the migrated shell rules through the current pipeline.
- Migration of shared-shell styling and behavior away from SB Admin 2 and Bootstrap 4-era shell assumptions where needed for sidebar, topbar, page-header, and shell-level layout treatment.
- Replacement of SB Admin 2-dependent and jQuery-driven shared-shell behavior with repo-owned shared-shell behavior implemented through current shared fragments and frontend assets where the touched shell area is being modernized.
- Introduction of Bootstrap 5-compatible shared-shell markup and behavior conventions for touched shell areas.
- Introduction of ScholarDex-owned visual primitives and support for both light and dark themes at the shared-shell/foundation level.

## Out Of Scope / Non-Goals

- No page-specific table/list redesign; that belongs to `H31`.
- No form/workflow redesign; that belongs to `H32`.
- No dashboard/feedback redesign; that belongs to `H33`.
- No route-family ownership changes.
- No page-specific shell forks or alternate shell composition paths.
- No separate runtime asset contract.
- No parallel frontend structure outside the existing `frontend/src/** -> /assets/app.css,/assets/app.js` pipeline.
- No unrelated backend/API/schema changes.

## Implementation Constraints

- Shared shell changes must route through shared fragments, with `src/main/resources/templates/fragments.html` as the primary implementation boundary for sidebar/topbar shell work.
- Existing role-aware sidebar composition is preserved; `H30` may refine its presentation but must not replace it with page-specific wiring.
- Authored CSS/JS changes must stay within the existing frontend build and verification flow.
- Admin-only pages remain under `/admin/**`.
- User-owned flows remain under `/user/*`.
- Shared entity pages remain entity-first and role-aware.
- `H30` must not deepen or expand SB Admin 2, Bootstrap 4-only, or jQuery-driven UI dependency while migrating the shared shell.
- Transitional third-party assets and inline-script exceptions remain explicit and guarded; `H30` does not silently expand those exceptions.
- Current implementation details such as the `Switch Workspace` dropdown may be improved in place, but `H30` does not authorize inventing separate shell patterns per page family.
- Touched shared-shell implementation should converge on Bootstrap 5-compatible markup/data APIs and repo-owned behavior.
- Later tasks should treat the shared-shell ownership model, `data-bs-theme` root contract, and shell-level layout primitives as fixed inherited foundations unless a new active contract explicitly reopens them.

## Acceptance Evidence Targets

- `H30.2` migrates shared sidebar treatment without bypassing the unified sidebar composition path.
- `H30.3` migrates shared topbar and page-header orientation through shared fragments.
- `H30.4` introduces shell-level visual primitives, theme hooks, and light/dark support through the current frontend asset pipeline.
- Touched shared-shell areas no longer depend on SB Admin 2 styling/behavior, Bootstrap 4-era shell conventions, or jQuery-driven shell behavior where the slice replaces those areas.
- `H30.5` aligns active docs and touched guardrails with the refreshed shared-shell baseline.
- `H31` owns table/list migration; `H32` owns form/workflow and modal/tooltip migration; `H33` owns dashboard/summary/feedback migration; `H34` owns remaining remnant cleanup, accessibility, and cross-theme consistency closeout.

## Verification Expectations

Minimum targeted verification for touched shared-shell work under `H30`:

- `npm run build`
- Route/shared UI changes: `npm run verify-route-guardrails`
- Template/asset contract: `npm run verify-assets`
- Template/runtime asset usage: `npm run verify-template-assets`
- Guarded route/UI surfaces only: `npm run verify-ui-guardrails`

Broader validation should be selected from `docs/quality-gates.md` based on the exact touched area. This contract names the minimum targeted checks for shared-shell work; `verify-ui-guardrails` remains a narrow conditional check, not a universal shell command.
