# H28.1 Descriptive Runtime Naming Contract

Date: 2026-03-30  
Status: archived

## Summary
H28.1 locked the runtime-only naming cleanup for legacy `Hxx` identifiers that still appeared as live Java types, runtime-facing labels, or present-tense operational/log text.

This contract applied to runtime code and runtime-facing strings only. Historical task ids remain valid in archived task/docs material and were intentionally out of scope.

Locked defaults:
- operational-status family renames to `PostgresOperationalStatus*`
- `H19CanonicalMetrics` renames to `CanonicalObservabilityMetrics`
- Micrometer meter ids under `core.h19.*` remain unchanged in H28
- public routes and JSON wire contracts remain unchanged

## Locked Rename Map

### Operational status family
- `H22OperationalStatusService` -> `PostgresOperationalStatusService`
- `DefaultH22OperationalStatusService` -> `DefaultPostgresOperationalStatusService`
- `H22OperationalStatusSnapshot` -> `PostgresOperationalStatusSnapshot`
- `ComponentStatus` remains descriptive enough and does not require a task-id-specific rename by itself unless implementation pressure later requires scoping it under the renamed parent type.

### Canonical observability helper
- `H19CanonicalMetrics` -> `CanonicalObservabilityMetrics`

## Propagation Rules
- Runtime imports, injections, constructor parameters, nested type references, and test class names move with the renamed types.
- Admin UI labels/messages that currently say `H22 operational status` must move to descriptive Postgres operational-status wording.
- Runtime strings/comments/template headings/property comments that currently use `H22.3`, `H22.5`, or `H22.7` as present-tense labels are in scope for replacement with capability-based wording.

## Runtime String And Comment Cleanup Buckets
These were explicitly in scope for later H28 implementation subtasks:
- `AdminInitializationController` flash/error text that currently mentions `H22 operational status`
- `admin/initialization.html` headings currently showing:
  - `Postgres Reporting Projection (H22.3)`
  - `Postgres Materialized Views (H22.5)`
  - `H22 Operational Status (H22.7)`
- `application-postgres.properties` comments mentioning `H22.2` / `H22.3`
- `JdbcPostgresReportingProjectionService` log labels that currently say `H22.3 ...`
- `PostgresReadCutoverGuard` exception text mentioning completed `H22.3 projection checkpoints`

## Explicit Non-Goals
The following were not renamed in H28:
- public HTTP routes and JSON wire contracts
- archived task ids in `TASKS-done.md`
- `docs/tasks/closed/**`
- historical references in narrative docs where `Hxx` is clearly archival evidence rather than current runtime naming
- Micrometer meter ids:
  - `core.h19.canonical.build.duration`
  - `core.h19.canonical.build.runs`
  - `core.h19.reconcile.duration`
  - `core.h19.reconcile.runs`
  - `core.h19.source_link.transitions`
  - `core.h19.identity_conflict.created`

## Public Contract Boundaries
No route or JSON contract changes were part of H28.

Unchanged route families:
- `/admin/initialization/postgres/operational/*`
- `/admin/initialization/postgres/projection/*`
- `/admin/initialization/postgres/materialized/*`

## Notes
- `PostgresOperationalStatus*` was the locked naming family because it matches the current admin/operator route surface and the runtime behavior of the service.
- `CanonicalObservabilityMetrics` is intentionally broader than `IngestionMetrics` because the helper records canonical builds, reconcile runs, source-link transitions, and conflict creation.
- Meter ids stayed unchanged in this task to avoid dashboard/alert churn during a pure naming cleanup.
