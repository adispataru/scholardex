# Component Library Debt

Status: active technical-debt note for H44.11.

The H44 shared components are available, but several older surfaces still carry ad-hoc implementations. Do not sweep these outside a focused UI task; migrate them when the owning page is next touched.

## Remaining Ad-Hoc Usages

- Raw modal shells remain on older create/import dialogs, including admin groups, indicators, domains, activities, reports, institutions, and the user citation detail modal. Prefer `modal-shell(...)` plus `window.appModal` when those flows are modernized.
- Client-rendered pager controls still use `.app-table-pager` in ranking/forum directory pages and some admin Scholardex directory pages. Prefer shared `pagination(...)` or `clientPagination.js` when those table controllers are revisited.
- Hand-authored `.app-summary-grid` blocks remain on dashboard/workspace/reporting pages where values are assembled inline. Prefer `stat-card-grid(cards)` for server-provided metrics and keep client-generated grids only where the data is fully client-side.
- Some legacy filter/search surfaces still use page-local controls, especially admin Scholardex directory filters and URAP/university filters. Prefer `filter-panel(...)` and `search-input(...)` for touched form-backed filters.
- A legacy `confirm(...)` remains in `individual-report-dashboard.js` for snapshot deletion. Replace it with `window.appConfirmDialog.open(...)` when that static JS flow is next modernized.
- Hand-built admin breadcrumbs remain on group and institution workspace pages. Prefer `admin-breadcrumb(items)` with `BreadcrumbItem` when those controllers are next touched.

## Verification Reminder

After migrating any item above, run the normal frontend checks for the touched surface: `npm run build`, `npm run verify-assets`, `npm run verify-template-assets`, `npm run verify-ui-guardrails` when applicable, and targeted MVC/JS tests for the page.
