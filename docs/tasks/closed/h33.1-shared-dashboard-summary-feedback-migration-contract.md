# H33.1 Shared Dashboard/Summary/Feedback Migration Contract

Status: archived dashboard/summary/feedback migration contract for completed H33 baseline.

## Purpose

Record what `H33` established and the migration boundary it leaves for later work.

This doc began as the decision lock for `H33`. It now serves as the contributor-facing record of the dashboard, summary, and feedback baseline established by `H33` without reopening shell rework owned by `H30`, shared table/list work owned by `H31`, shared form/workflow work owned by `H32`, or final cleanup owned by `H34`.

`H33` is the dashboard, summary, and feedback migration layer for the broader UI modernization wave. It builds on the shared shell, theme, layout, table/list, and workflow baseline established by `H30`, `H31`, and `H32` and defines how dashboard-like, summary-heavy, mixed workspace, and feedback-heavy surfaces should migrate toward a ScholarDex-owned, Bootstrap 5-compatible, light/dark-capable summary and feedback system.

## Post-H33 Baseline

- The shared shell, theme contract, bounded content layout, shared table/list baseline, and shared workflow baseline are already established by `H30`, `H31`, and `H32`.
- Runtime templates continue to consume frontend assets through `/assets/app.css` and `/assets/app.js`.
- Authored frontend changes still flow through `frontend/src/**` and the existing asset build pipeline.
- The shared summary and feedback foundation now lives under `frontend/src/**` and flows through `/assets/app.css` with repo-owned classes for summary grids, summary cards, summary panels, chart frames, empty states, attention blocks, and feedback surfaces.
- Primary shared/admin summary surfaces now use the shared ScholarDex contract instead of stacked SB Admin stat cards and raw alert framing on pages such as `admin/dashboard`, `admin/conflicts`, `admin/source-links`, `admin/wos-enrichment`, and `admin/user-defined-triage`.
- Mixed user workspace surfaces now use the same summary and feedback language on pages such as `user/tasks`, `user/activities`, `user/profile`, `user/publications` summary framing, and `user/individual-report-view`.
- Touched H33 surfaces no longer treat placeholder dashboards, stacked SB Admin summary cards, page-local chart wrappers, or raw Bootstrap 4 alert/card presentation as the intended UX baseline.
- Touched list/table and workflow pages continue to inherit the `H31` and `H32` baselines where summary framing hands off into tables or workflow sections.

## Locked Direction

- ScholarDex-owned dashboard, summary, and feedback patterns are the intended UX baseline for touched summary-heavy and feedback-heavy surfaces.
- Bootstrap 5-compatible markup and behavior direction apply to touched dashboard/summary/feedback work.
- Light and dark themes are supported presentation modes within one shared summary and feedback system.
- SB Admin stat-card presentation, placeholder dashboard framing, and Bootstrap 4-era alert/card treatment are transitional debt, not the target contract.
- `H33` should create one consistent summary and feedback language across shared, admin, and user surfaces rather than preserving page-by-page dashboard drift.
- `H33` builds on the H30 shell/theme baseline, the H31 table/list baseline, and the H32 workflow baseline and does not revisit shell, shared list ownership, or shared workflow ownership decisions.
- `H34` inherits the shared dashboard/summary/feedback vocabulary, migrated summary examples, and light/dark summary baseline established by `H33`.

## Established Examples

- Shared/admin summary examples: `admin/dashboard`, `admin/conflicts`, `admin/source-links`, `admin/wos-enrichment`, `admin/user-defined-triage`
- Mixed user workspace examples: `user/tasks`, `user/activities`, `user/profile`, `user/publications`, `user/individual-report-view`
- Shared feedback surfaces now own visible action outcomes on touched summary-heavy pages instead of one-off raw alert treatment.

## What H33 Established

- Shared dashboard/summary/feedback foundation under `frontend/src/**`.
- Metric cards, summary bands, attention or health blocks, recent-activity sections, quick-action clusters, chart containers, and empty-state guidance.
- Consistent inline and surface-level success, error, warning, pending, and status messaging for touched summary-heavy or action-heavy surfaces.
- Migration of the primary shared/admin dashboard-like and summary-heavy surfaces to the shared ScholarDex summary contract.
- Migration of the primary mixed user workspace, dashboard-like, chart-plus-table, and feedback-heavy surfaces intentionally deferred from `H32`.
- Docs and verification alignment for the dashboard/summary/feedback baseline established by `H33`.

## Remaining Boundary For Later Work

- No shell, sidebar, topbar, page-header, or theme-state work owned by `H30`.
- No shared table/list foundation work owned by `H31`.
- No shared form/workflow foundation work owned by `H32`.
- No final accessibility, responsive, or remnant-cleanup closeout owned by `H34`.
- No unrelated backend, API, persistence, or schema changes.
- No repo-wide one-shot redesign of every page that happens to contain a chart, card, or alert before `H34` closes the remaining remnant work.

## Implementation Constraints

- Use the existing frontend asset pipeline and `/assets/app.css` + `/assets/app.js`.
- Inherit the `H30` theme contract, including `data-bs-theme` on the root element as the shared theme-state source of truth.
- Inherit the `H31` table/list contract where summary pages hand off into migrated tables.
- Inherit the `H32` workflow contract where mixed pages combine summary framing with form or action flows.
- Do not introduce new Bootstrap 4-only card, alert, collapse, or dashboard presentation patterns.
- Do not introduce new page-local notification systems or one-off feedback conventions as the intended steady-state interaction model.
- Touched templates should converge on one shared dashboard/summary/feedback contract instead of page-local summary systems.
- If Bootstrap-era or page-local dashboard behavior remains on a touched page temporarily, the visible summary and feedback presentation must still be ScholarDex-owned rather than stock SB Admin or Bootstrap 4.
- Shared/admin summary surfaces and mixed user workspace surfaces remain separate migration slices under the same shared dashboard/summary/feedback foundation.

## Acceptance Evidence Targets

- `H33.2` establishes the shared dashboard/summary/feedback foundation.
- `H33.3` migrates primary shared/admin dashboard-like and summary-heavy surfaces.
- `H33.4` migrates primary mixed user dashboard, workspace-summary, and feedback-heavy surfaces.
- `H33.5` aligns docs and guardrails with the post-H33 baseline.
- Touched surfaces no longer treat stacked SB Admin stat cards, placeholder dashboard shells, or Bootstrap 4 alert/card treatment as the intended UX baseline.
- Dashboard/summary migration covers metric hierarchy, attention and recent-activity framing, empty-state guidance, and explicit action-outcome messaging rather than only card restyling.
- `H34` owns remaining Bootstrap 4/SB Admin remnant cleanup, accessibility, responsive behavior, and final cross-theme consistency closeout for untouched dashboard or summary surfaces.

## Verification Expectations

Minimum targeted verification for touched `H33` implementation slices:

- `npm run build`
- `npm run verify-assets`
- `npm run verify-template-assets`
- `npm run verify-route-guardrails`
- `npm run verify-ui-guardrails` only when touched dashboard/summary pages intersect the route/UI surfaces already protected by that script

Broader validation should continue to come from `docs/quality-gates.md` based on the exact touched area. This contract names the minimum targeted checks for dashboard/summary/feedback migration slices; `verify-ui-guardrails` remains a narrow conditional check, not a universal dashboard command.
