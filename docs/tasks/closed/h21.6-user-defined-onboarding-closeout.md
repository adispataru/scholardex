# H21.6 USER_DEFINED Onboarding Closeout

Status: closeout note for H21 user-defined source onboarding into Scholardex.

## Purpose

Record the shipped state of the in-place `/user/publications/add` migration into canonical `USER_DEFINED` onboarding and archive the H21 task artifacts.

## Shipped Outcome

The user publication wizard remains at:

- `GET /user/publications/add`

The submit path now emits canonical `USER_DEFINED` onboarding through the import-event pipeline rather than relying on a legacy manual compatibility path.

Steady-state behavior:

- source family is `USER_DEFINED`,
- new wizard-created forum/publication lineage uses deterministic `USER_DEFINED:FORUM:*` and `USER_DEFINED:PUBLICATION:*` source-record IDs,
- wizard publication EIDs use `USER_DEFINED:EID:*`,
- wizard submissions persist explicit review/moderation metadata with `PENDING_OPERATOR_REVIEW`,
- USER_DEFINED source facts canonicalize into Scholardex publication/forum facts and feed the existing projection pipeline,
- selected existing canonical forum IDs are preserved when the wizard targets an existing forum.

## Operability And Admin Surfaces

Shipped H21 operator surfaces:

- `GET /admin/user-defined-triage`
- `POST /admin/initialization/user-defined/buildFacts`
- `POST /admin/initialization/user-defined/canonicalize`
- `POST /admin/initialization/user-defined/runAll`

The diagnostics/triage path remains read-only and deep-links into:

- `/admin/source-links?source=USER_DEFINED`
- `/admin/conflicts?incomingSource=USER_DEFINED`
- `/admin/initialization`

No separate admin approval workflow was introduced.
