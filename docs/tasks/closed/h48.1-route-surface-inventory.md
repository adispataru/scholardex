# H48.1 Route And Surface Inventory

**Status:** Completed
**Created:** 2026-04-28
**Completed:** 2026-04-28

## Purpose

Define the canonical UX audit surface for `H48` from current controllers, runtime templates, security rules, and existing guardrails.

This note is intentionally route-family based rather than listing every POST handler. `H48` needs a stable audit matrix for browser verification, static guardrails, and redirect-only compatibility routes. The matrix below identifies which surfaces need browser coverage, which are better covered by controller/guardrail tests, and which templates/routes are stale or broken before deeper audit work starts.

## Sources Used

- `src/main/java/ro/uvt/pokedex/core/config/WebSecurityConfig.java`
- MVC controllers under `src/main/java/ro/uvt/pokedex/core/view/**`
- `scripts/verify-route-guardrails.js`
- `scripts/verify-ui-guardrails.js`
- Runtime templates under `src/main/resources/templates/**`

## Verification Depth Rules

- `browser`: full browser audit surface for accessibility, theme, and responsive checks.
- `static guardrail`: route/template should be protected by static checks and targeted controller tests; browser coverage is not the primary mechanism.
- `redirect-only`: compatibility route or shell redirect; verify via controller/security contract tests rather than visual audit.
