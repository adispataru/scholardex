# H35.1 Legacy Asset Extraction And Steady-State Cleanup Contract

Status: archived contract lock for completed H35 legacy asset extraction and steady-state shell cleanup.

## Purpose

Lock the remaining frontend cleanup contract before implementation work under `H35`.

This slice is documentation-only. It records what must be extracted from the active ScholarDex frontend baseline, which shared shell/footer behaviors must be corrected once legacy assets stop masking them, and how page-visible migration copy must be treated going forward.

`H35` is a new wave, not a reopening of `H30`-`H34`. Those waves established and closed the ScholarDex-owned shell, list/table, workflow, summary, accessibility, responsive, and migration-closeout baseline for migrated families. `H35` exists to remove the remaining legacy asset/runtime dependency and finish the steady-state polish that still sits on top of that baseline.

## Current Baseline

- Authenticated runtime templates resolve shared shell behavior through `src/main/resources/templates/fragments.html`.
- The authored frontend asset contract is `/assets/app.css` and `/assets/app.js`, built from `frontend/src/**`.
- The current authenticated baseline still includes legacy asset/runtime coupling:
  - many templates still include `/css/sb-admin-2.min.css`
  - `fragments.html` still includes `/js/sb-admin-2.min.js`
  - `frontend/src/app.js` still imports Bootstrap CSS/JS and BS4 DataTables styling/runtime
- The shared footer fragment is still legacy-shaped and still depends on a footer message property whose current value is encoding-corrupted.
- Dark-mode authenticated pages still show visual conflict between ScholarDex-owned card/surface tokens and legacy shell/background treatment.
- Some page-visible intro/help text still references migration history, old Bootstrap patterns, or internal contract language rather than describing page purpose.

## Locked Direction

- `H35` is the final extraction and polish wave for the active authenticated frontend baseline, not another redesign wave.
- SB Admin 2 CSS/JS and Bootstrap 4 imports are no longer acceptable steady-state dependencies for authenticated ScholarDex surfaces.
- Shared fragments plus `/assets/app.css` and `/assets/app.js` are the intended sole steady-state shell asset contract for authenticated pages after `H35`.
- Shared footer styling and footer copy must be governed by ScholarDex-owned shell/theme primitives, not legacy footer classes or corrupted property text.
- Dark-mode authenticated pages must use the repo-owned shell background contract rather than legacy white/backdrop behavior inherited from SB Admin.
- Page-visible copy must describe page purpose and operator/user intent only, not migration history, old implementation debt, or internal frontend-contract language.

## In Scope

- Shared fragment asset contract in `src/main/resources/templates/fragments.html`.
- Frontend asset entrypoint in `frontend/src/app.js`.
- Shared footer fragment and footer message source.
- Shared shell background/theme behavior for authenticated pages.
- Page-visible migration copy on already-migrated and explicitly targeted legacy pages touched by the extraction work.
- Targeted legacy pages that are still being modernized as part of the next extraction pass.
- Docs and guardrails needed to describe the post-H35 steady-state baseline.

## Out Of Scope / Non-Goals

- No route, controller, API, schema, or business-workflow changes.
- No redesign wave-two visual exploration beyond the cleanup needed to establish a neutral steady-state baseline.
- No requirement to reopen unrelated untouched public, auth, or error pages unless a later task explicitly brings them into scope.
- No page-family redesign that belongs to future design work once legacy asset extraction is complete.
- No silent expansion of scope from authenticated steady-state cleanup into repo-wide frontend replacement.

## Implementation Constraints

- `H35` must treat shared fragments and the existing frontend asset pipeline as the primary extraction boundary.
- Authored CSS/JS changes must continue to flow through `frontend/src/**` and the existing asset build path.
- Touched authenticated templates should converge on the ScholarDex-owned shell/theme contract without SB Admin or Bootstrap 4 runtime styling dependencies.
- Footer text must be sourced from a clean UTF-8-safe value and remain configurable through existing property patterns.
- Migration-copy cleanup must preserve page meaning and operator guidance while removing references to:
  - migration status
  - “old Bootstrap 4”
  - “shared contract”
  - similar internal implementation history
- Remaining bounded legacy debt after `H35` must be explicit in docs if any untouched non-authenticated or deferred legacy pages still depend on Bootstrap-era assets.

## Expected Follow-On Implementation Buckets

- Shared asset/fragments extraction.
- Footer and dark-shell background correction.
- Migration-copy purge across touched pages.
- Docs and guardrail alignment for the post-H35 baseline.

## Acceptance Evidence Targets

- Shared fragments no longer include SB Admin 2 CSS/JS as part of the authenticated baseline.
- `frontend/src/app.js` no longer imports Bootstrap 4 CSS/JS or BS4 DataTables styling/runtime for the modernized baseline.
- Shared footer text renders correctly and no longer shows corrupted encoding.
- Dark-mode authenticated pages use the repo-owned shell background instead of white or legacy SB Admin backdrops.
- Touched page copy no longer references “migration”, “old Bootstrap 4”, “shared contract”, or similar internal implementation history.
- Docs and quality-gate guidance reflect the post-H35 baseline and any intentionally bounded remaining legacy debt.

## Verification Expectations

Minimum targeted verification for touched work under `H35`:

- `npm run build`
- `npm run verify-assets`
- `npm run verify-template-assets`
- `npm run verify-route-guardrails`
- `npm run verify-ui-guardrails` only when touched files intersect the guarded UI surfaces

Broader validation should be selected from `docs/quality-gates.md` based on the exact extraction scope. This contract names the minimum targeted checks for the H35 baseline work; it does not introduce new verification commands.
