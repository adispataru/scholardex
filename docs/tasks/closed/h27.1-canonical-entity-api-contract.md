# H27.1 Canonical Entity API Contract

Status: archived contract lock for H27.1.

## Purpose

Lock the breaking public API migration for Scholardex-backed author, forum, and affiliation entity reads.

This slice was contract-definition only. Its role was to decision-lock the public route family, DTO naming direction, preserved wire shape, and explicit breaking-change policy before H27.2-H27.4 changed runtime behavior.

## Canonical Route Family

The canonical public route family for these entity-read APIs is:

- `GET /api/entities/authors`
- `GET /api/entities/forums`
- `GET /api/entities/affiliations`

These routes replaced the legacy public compatibility routes:

- `GET /api/scopus/authors`
- `GET /api/scopus/forums`
- `GET /api/scopus/affiliations`

## Breaking-Change Policy

H27 is an intentional breaking public API migration.

The migration policy is:

- `/api/scopus/authors`, `/api/scopus/forums`, and `/api/scopus/affiliations` are removed in H27.2-H27.3.
- No redirect, alias, or dual-route compatibility window is retained.
- Documentation and automated contract/security coverage are updated in the same migration wave.
- H27.4 adds explicit negative coverage for removed `/api/scopus/**` entity-read routes.

This contract applies only to the author, forum, and affiliation entity-read APIs. It does not change `/api/rankings/wos`, publication APIs, or any admin/MVC route family.

## Contract Continuity

Unless H27.1 explicitly says otherwise, the canonical `/api/entities/**` routes preserve runtime behavior from the former `/api/scopus/**` entity-read APIs.

The preserved continuity rules are:

- Same paging envelope fields: `items`, `page`, `size`, `totalItems`, `totalPages`
- Same validation and bad-request handling behavior from `ApiExceptionHandler`
- Same unauthorized/forbidden API security posture as the prior read APIs
- Same query parameter semantics
- Same allowed sort keys
- Same query normalization intent and error-envelope shape

The preserved error envelope is the existing `ApiErrorResponse` shape:

- `timestamp`
- `status`
- `error`
- `path`
- `message`

## Public DTO Naming Direction

The public DTO naming direction is `Scholardex*`, not `Entity*` and not `Scopus*`.

Target response naming:

- `ScholardexAuthorPageResponse`
- `ScholardexAuthorListItemResponse`
- `ScholardexForumPageResponse`
- `ScholardexForumListItemResponse`
- `ScholardexAffiliationPageResponse`
- `ScholardexAffiliationListItemResponse`

This is a public contract rename even though the external route family is `/api/entities/**`.

## Source Of Truth And Supersession

This document supersedes the earlier “keep intentionally” posture for `/api/scopus/**` for these three entity-read APIs only.

Specifically:

- earlier H23 inventory and handoff notes that retained `/api/scopus/**` as a stable public API remain historical evidence,
- H27.1 was the source of truth for author/forum/affiliation entity-read API migration intent during implementation,
- `/api/rankings/wos` remains out of scope and is not affected by this contract.

## Implemented Outcome

H27.2-H27.4 implemented this contract with the following shipped outcome:

- controller mappings moved from `/api/scopus/**` to `/api/entities/**`,
- `Scopus*` public response types were replaced by `Scholardex*` public response types,
- response JSON field names remained unchanged,
- API contract tests and API security tests moved to `/api/entities/**`,
- removed `/api/scopus/**` entity-read routes now have explicit negative tests,
- active docs and closeout notes no longer describe `/api/scopus/**` as supported for these three APIs.

## Out Of Scope

This contract lock does not cover:

- `/api/rankings/wos`
- publication read APIs
- admin MVC routes
- user MVC routes
- internal Java package renames unrelated to the public API contract
