# H34.1 Accessibility, Responsive, And Closeout Contract

Status: archived H34 accessibility, responsive, and closeout contract established on 2026-04-02.

## Purpose

Record the implementation contract that `H34` established for the final UI modernization closeout wave.

This task doc is archived as the contract source of truth for the completed `H34` wave. It existed to keep `H34` from drifting back into shell redesign already owned by `H30`, shared table/list redesign already owned by `H31`, shared form/workflow redesign already owned by `H32`, or shared dashboard/summary redesign already owned by `H33`. It also gave `H34.2`-`H34.8` a decision-locked closeout boundary so they could execute as focused incremental adjustments instead of a vague repo-wide polish pass.

`H34` was the accessibility, responsive-behavior, cross-theme-consistency, and remnant-cleanup closeout layer for the broader UI modernization wave. It built on the shared shell, table/list, form/workflow, and dashboard/summary baseline established by `H30`, `H31`, `H32`, and `H33`.

## Post-H33 Baseline

- The shared shell and theme-state contract are already established by `H30`.
- The shared table/list contract is already established by `H31`.
- The shared form/workflow contract is already established by `H32`.
- The shared dashboard/summary/feedback contract is already established by `H33`.
- Runtime templates continue to consume frontend assets through `/assets/app.css` and `/assets/app.js`.
- Authored frontend changes still flow through `frontend/src/**` and the existing asset build pipeline.
- Migrated surfaces now already use ScholarDex-owned shell, table, workflow, and summary systems across shared, admin, and user page families.
- Remaining Bootstrap 4, SB Admin, and compatibility-era presentation on those already-migrated families is now closeout debt, not acceptable steady state.
- Accessibility semantics, visible focus treatment, keyboard reachability, responsive behavior, and cross-theme parity were the main quality gaps left to close across the migrated surface families.

## Locked Direction

- ScholarDex-owned shell, table, workflow, and summary systems remain the inherited UX baseline for touched `H34` work.
- Bootstrap 5-compatible markup and behavior direction remain in force for touched closeout work.
- Light and dark themes are supported presentation modes within one shared frontend system, and `H34` owns remaining cross-theme consistency gaps on already-migrated families.
- `H34` is a closeout layer on already-migrated surfaces first, not a new redesign wave.
- Accessibility, keyboard/focus correctness, visible state messaging, responsive overflow and wrapping, and cross-family consistency are the primary quality targets for `H34`.
- Remaining Bootstrap 4/SB Admin wrapper and presentation remnants on already-migrated surfaces are transitional debt that `H34` should remove incrementally.

## Established Examples And Owned Families

- User table/report families: `user/publications`, `user/citations`, `user/indicators`, `user/individual-reports`, and related report/list pages.
- User workflow/workspace families: `publications-add-step*`, `indicators-apply-*`, `user/activities`, `user/tasks`, and `user/profile`.
- Shared/admin list-table families: `forums`, `rankings`, `categories`, `universities`, and `admin/scholardex-*`.
- Admin workflow families: `admin/users`, `admin/domains`, `admin/institutions`, `admin/groups`, `admin/indicators*`, `admin/activities*`, `admin/*Reports*`, `edit-group`, and `edit-institutions`.
- Dashboard/summary/workspace families: `admin/dashboard`, `admin/conflicts`, `admin/source-links`, `admin/wos-enrichment`, `admin/user-defined-triage`, `user/tasks`, `user/activities`, `user/profile`, `user/publications`, and `user/individual-report-view`.
- Remnant cleanup applies across already-migrated shell, table, workflow, and summary families rather than across untouched legacy pages.

## In Scope

- Accessibility semantics, keyboard reachability, visible focus treatment, and state/status messaging on already-migrated page families.
- Responsive overflow, wrapping, spacing, breakpoint behavior, and chart/table coexistence on already-migrated page families.
- Light/dark parity and cross-theme consistency across already-migrated shell, table, workflow, and summary systems.
- Targeted removal of stale Bootstrap 4/SB Admin wrapper or presentation remnants from already-migrated surfaces.
- Docs and verification alignment for the final post-migration frontend baseline established by `H34`.

## Out Of Scope / Non-Goals

- No new shell redesign work already completed or bounded by `H30`.
- No new table/list redesign work already completed or bounded by `H31`.
- No new form/workflow redesign work already completed or bounded by `H32`.
- No new dashboard/summary redesign work already completed or bounded by `H33`.
- No unrelated backend, API, persistence, or schema changes.
- No repo-wide rewrite of untouched legacy pages just because they still contain Bootstrap 4 or SB Admin artifacts.
- No reopening of prior ownership boundaries unless a new active contract explicitly does so.

## Implementation Constraints

- Use the existing frontend asset pipeline and `/assets/app.css` + `/assets/app.js`.
- Inherit the `H30` theme contract, including `data-bs-theme` on the root element as the shared theme-state source of truth.
- Inherit the `H31` table/list contract where touched closeout work applies to migrated list or report surfaces.
- Inherit the `H32` workflow contract where touched closeout work applies to migrated form, modal, or workflow surfaces.
- Inherit the `H33` summary/feedback contract where touched closeout work applies to migrated dashboard, summary, or mixed workspace surfaces.
- Do not introduce new Bootstrap 4-only UI patterns while closing existing remnants.
- Do not introduce new page-local accessibility, status, or feedback conventions as the intended steady-state model.
- Keep closeout work incremental and family-scoped rather than broad repo-wide rewrites.
- If untouched legacy pages still carry Bootstrap-era debt, that debt remains bounded unless a later active task explicitly reopens those surfaces.

## Acceptance Evidence Targets

- `H34.2` closes accessibility and focus/state gaps on migrated user table and report families.
- `H34.3` closes accessibility and focus/state gaps on migrated user workflow and workspace families.
- `H34.4` closes responsive and cross-theme consistency gaps on migrated shared and admin list/table families.
- `H34.5` closes responsive and cross-theme consistency gaps on migrated admin workflow families.
- `H34.6` closes responsive and cross-theme consistency gaps on migrated dashboard, summary, and workspace families.
- `H34.7` removes remaining Bootstrap 4 and SB Admin presentation remnants from already-migrated families.
- `H34.8` aligns docs, guardrails, and the final post-migration frontend baseline.
- Touched `H34` surfaces no longer treat accessibility, focus, responsive behavior, or cross-theme parity as deferred concerns.
- Already-migrated surfaces no longer carry stale Bootstrap 4/SB Admin presentation as part of their visible contract.

## Verification Expectations

Minimum targeted verification for touched `H34` implementation slices:

- `npm run build`
- `npm run verify-assets`
- `npm run verify-template-assets`
- `npm run verify-route-guardrails`
- `npm run verify-ui-guardrails` only when touched files intersect the route/UI surfaces already protected by that script

Broader validation should continue to come from `docs/quality-gates.md` based on the exact touched area. This contract names the minimum targeted checks for `H34` implementation slices; `verify-ui-guardrails` remains a narrow conditional check, not a universal closeout command.
