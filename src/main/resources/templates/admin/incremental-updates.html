When To Use This Page

/admin/incremental-updates is for one uploaded file at a time when you want to ingest a new WoS or Scopus payload and run only the incremental maintenance steps wired into that source upload.

/admin/initialization remains the place for broader maintenance, rebuild, reconcile, recovery, and downstream follow-up steps after an upload run.

WoS Incremental Upload

Choose the WoS source family explicitly, then upload exactly one matching file. Accepted files are official .json exports or government .xls/.xlsx AIS/RIS workbooks.

WoS upload scope

This action runs WoS ingest plus WoS fact building for the uploaded file lineage. Upload-scoped category enrichment and upload-scoped projection rebuild are available below after a successful WoS upload. Use Initialization for full-corpus WoS onboarding, recovery, canonical reset, or broader rebuild maintenance.

Use OFFICIAL_JSON for Web of Science JSON exports and GOVERNMENT_EXCEL for AIS/RIS Excel files.

Matches the existing WoS initialization convention when the operator wants to override inferred source versioning.

One file per run. Supported extensions depend on the selected source type.

Scopus Incremental Upload

Upload exactly one Scopus .json file. Source version is not used for this upload flow.

Scopus upload scope

This action runs Scopus ingest, fact build, and canonical materialization for the uploaded payload. It does not run projection rebuild, source-link reconciliation, edge reconciliation, or ensure-indexes. Use Initialization for downstream Scopus maintenance after the upload if those steps are needed.

Only .json is accepted for Scopus incremental updates.

Expected columns: Publication Name, ISSN, sourceId, Aggregation Type, Publisher, ISBN. Emits FORUM events that update existing forum facts; the build step rebuilds canonical facts.
