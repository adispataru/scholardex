When To Use This Page

/admin/incremental-updates is for one uploaded file at a time when you want to ingest a new WoS or Scopus payload and run only the incremental maintenance steps wired into that source upload.

/admin/initialization remains the place for broader maintenance, rebuild, reconcile, recovery, and downstream follow-up steps after an upload run.

Upload failed
The upload contract was enforced before the run completed. Use initialization for broader maintenance, not for retrying the same file contract.
Upload completed
The counts below reflect only the subset of the pipeline executed by this upload action. Use initialization for downstream maintenance that was intentionally skipped.
WoS Incremental Upload

Choose the WoS source family explicitly, then upload exactly one matching file. Accepted files are official .json exports or government .xls/.xlsx AIS/RIS workbooks.

WoS upload scope
This action runs WoS ingest plus WoS fact building for the uploaded file lineage.
It does not run category enrichment, projection rebuilds, or WoS onboarding.
Use Initialization for downstream WoS maintenance after the upload if those steps are needed.
Use OFFICIAL_JSON for Web of Science JSON exports and GOVERNMENT_EXCEL for AIS/RIS Excel files.
Matches the existing WoS initialization convention when the operator wants to override inferred source versioning.
One file per run. Supported extensions depend on the selected source type.
Scopus Incremental Upload

Upload exactly one Scopus .json file. Source version is intentionally not part of this v1 contract.

Scopus upload scope
This action runs Scopus ingest, fact build, and canonical materialization for the uploaded payload.
It does not run projection rebuild, source-link reconciliation, edge reconciliation, or ensure-indexes.
Use Initialization for downstream Scopus maintenance after the upload if those steps are needed.
Only .json is accepted for Scopus incremental updates.
