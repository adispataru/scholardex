The data pipeline, operated by hand. Source files on the data volume (/app/data) become an event ledger, the ledger becomes source facts, the facts become the canonical layer (publications, authors, forums, edges) and the canonical layer is projected into the Postgres read model the reports run on. Every button here is synchronous — the page waits for the result and the app keeps serving — and idempotent unless marked destructive. Durations are from the full corpus (≈175k publications). The researchers' own syncs (Scopus, OpenAlex) run from the workspace and the scheduler, not from here.

Open Incremental Uploads

General Initialization

Bootstrap and the reference lists that classify venues: each import reads its file under data/ (URAP, ARWU, QS, CNCSIS, CORE, SENSE, artistic events) and replaces the list it owns. Safe to rerun when a file changes.

Run the bootstrap steps and the ranking imports

Admin user, special domain, artistic events, URAP, CNCSIS, CORE and SENSE — in that order, each reported separately. ARWU, QS and the DBLP sweep are not included; run them below.

Full derived-data rebuild (WoS + Scopus)

Destructive, long. Wipes every derived collection and re-derives the canonical layer and the projections from the source facts (WoS, Scopus, OpenAlex, USER_DEFINED, merges, claims, DBLP evidence): about 1.5 h on the full corpus, not resumable, and the reports are unavailable until it ends. Tick re-ingest only when a source file changed. Do not deploy or restart during the run. Prefer the targeted steps below for anything smaller; see docs/rebuild-runbook.md.

WoS Initialization

The journal-metrics side: the JCR / category extracts under data/wos-json-1997-2019 (plus the later years added since) become WoS forum, category and metric facts, then the WoS tables of the read model that the quartile, AIS and impact-factor rules query. Needed only when the extracts change (a new JCR year); run the steps in order. The citation counts and accession codes of the researchers' own papers come from the sweeps, not from these steps.

1. Ingest events

Reads the extract files into the WoS event ledger; files already ingested are skipped, so a rerun only adds new ones.

2. Build facts from events

Turns the ledger into forum / category / metric facts, resumable from its checkpoint (reset it below to start over).

3. Enrich category rankings

Computes each journal's rank inside its category per metric and year (the extract's own "rank" is by total cites and is never used); only missing ranks are filled — reset and rebuild to recompute.

4. Build projections

Rewrites the WoS tables of the Postgres read model (wos_*) from the facts; a few minutes.

5. Ensure indexes

Creates the Mongo indexes the WoS collections need; a no-op when present.

Reset fact-build checkpoint

Scopus Initialization

The historical Scopus corpus: the university's Scopus dump (data/scopus/…json) becomes a ledger and source facts, the canonical layer is derived from them together with the OpenAlex and USER_DEFINED facts, and 3. Build projections rewrites the whole Scholardex read model. Steps 1–2 are needed only when the dump changes; the canonical build and step 3 are the general "re-derive and publish" tools for every source.

1. Ingest events

Reads the Scopus dump into the event ledger (batches already ingested are skipped).

2. Build facts

Turns the ledger into Scopus publication / author / affiliation / citation facts, resumable from its checkpoint (start batch and chunk size override it).

3. Build projections

Rebuilds every Scholardex table of the Postgres read model (publications, authors, forums, memberships, metrics, citations, the citation-context view) from the canonical facts and bumps the reporting epoch so cached reports refresh. ~8 min. This is the step that publishes any canonical change to the reports — in this deployment it is what the Postgres projection wrapper below would call.

4. Ensure canonical indexes

Creates the non-unique performance indexes of the canonical collections (scholardex.*); a no-op when present. Run after a reset and whenever an author or forum lookup became slow.

Maintenance

Backfill canonical citations

Same as the canonical build with entity citation: re-derives the canonical citation edges from the Scopus citation facts. Kept for the old runbooks.

Backfill citation counts per source

Stamps the Scopus and OpenAlex citation counts on every canonical publication from the facts it is linked to (the best of a source's records when it holds several) and lifts the total where it is below them, without re-canonicalising anything; under a minute, safe to rerun. Follow with 3. Build projections so the pages show them.

Run canonical build

Re-derives the canonical layer from the Scopus facts — entity all, publication (~15 min), author, affiliation or citation — merging into the existing records (OpenAlex-owned fields are kept). Resumable from its checkpoint unless a start batch is given. Tick the reconciles to repair the source-link ledger and the edges at the end. Follow with 3. Build projections.

Options

Reconcile canonical edges

Walks every canonical publication and repairs its authorship and publication→author→affiliation edges to match its author list (missing ones added, stale provenance fixed). Cheap; run after a canonical build that was interrupted.

Reconcile source-link ledger

Normalises the source-link ledger (one link per source record, consistent state and ids); cheap. Run when a canonical build reports link conflicts.

Reset canonical build checkpoints

Forgets where the canonical builds stopped so the next run starts from the first batch. Not destructive by itself.

Clear canonical Scopus state

Destructive. Drops the Scopus ledger, facts, the canonical layer, the Scholardex tables of the read model and the checkpoints — every report scores 0 until the full rebuild has run. Only for a from-scratch rebuild.

USER_DEFINED Initialization

The publications researchers declare themselves (wizard, DOI-less books and chapters). The declaration is the source; these steps rebuild its facts and canonical records when the declaration code changed. The full derived-data rebuild re-creates them itself (chained since 2026-10-02 — earlier rebuilds dropped them until this maintenance was run by hand).

1. Build USER_DEFINED source facts

Rebuilds the USER_DEFINED source facts from the declarations; safe to rerun.

2. Canonicalize USER_DEFINED facts

Creates or updates the canonical publications and forums of the declarations (matching existing records by DOI / ISBN / title); with rebuild projections ticked it also runs the Scholardex projection build (~8 min).

Operations without a button

Started with curl -X POST against /admin/initialization/… (they answer JSON and most take a limit); the dry-run forms write nothing. Listed so nobody looks for them here.

  • Reference lists for venues: scopus/importSourceList (Scopus source list → serial forums; run before Scopus → 2), scopus/importBookList, scopus/importCiteScore, wos/importMjl (Master Journal List), forum/importDoaj, forum/importErih, openalex/importSourceApc (fee journals from the OpenAlex dumps), general/journalDatabases (the journal databases' title lists).
  • Forum identity: forum/onboardErih, forum/onboardDoaj (tag by ISSN), forum/dedup (shared ISSN / ERIH id clusters), forum/reconcile (the full forum rebuild: dedup → canonical → claims), wos/cpci/dryRun + apply (conference-proceedings coverage from the CPCI export).
  • Authors: author/reconcile, author/reconcile/fuzzy, author/reconcile/affiliation (the automatic merge passes), author/merge (an explicit merge of two ids), author/merges/reapply (replays the durable merges; also part of every rebuild), provisional/resolveDepartment (dry-run of a staff roster against the canonical authors).
  • OpenAlex: openalex/bulkImport (file-driven works + citers → source facts). openalex/canonicalize is insert-based and fails on a live corpus — use the full derived-data rebuild instead.
  • Sweeps and repairs: crossref/volumes/dryRun + apply (volume titles for the conference resolution), crossref/publishers/dryRun + apply (publishers of publisher-less books), wos/enrichment/run, scopus/replayBatch (replays one ingested batch through the incremental pipeline).
